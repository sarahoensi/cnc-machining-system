# Purpose

This document is the canonical inventory of the current frontend feature
structures. It is machine-readable Markdown intended for developers and AI
agents, not end-user documentation.

The inventory is intended to support future feature generators, template
selection, AI-assisted development, architecture reviews, and structural
validation. It describes the repository as it exists today and does not
normalize naming, folder layout, command contracts, or feature responsibilities.

# Stable Conventions

| Convention                                                                                    | Evidence                                                                                                                                                                                                                          | Notes for automation                                                                                         |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Page components use PascalCase `*Page.tsx`.                                                   | `TrianglePage.tsx`, `HelixPage.tsx`, `CuttingDataPage.tsx`, `TolerancesPage.tsx`, `ThreadsPage.tsx`, `FinishingPage.tsx`, `CylinderWeightPage.tsx`                                                                                | Stable enough for generator naming.                                                                          |
| Page controller hooks use `use*PageController`.                                               | `useTrianglePageController.ts`, `useHelixPageController.ts`, `useCuttingPageController.ts`, `useTolerancePageController.ts`, `useThreadsPageController.ts`, `useFinishingPageController.ts`, `useCylinderWeightPageController.ts` | Stable enough for generator naming.                                                                          |
| Calculator-like features use `api/client.ts`.                                                 | `right_triangle`, `helix`, `cuttingData`, `tolerances`, `threads`, `cylinder_weight`                                                                                                                                              | Low-level wrappers should use `tauriInvoke` from `src/shared/api/tauriClient.ts`.                            |
| Solver wrappers use `api/solve*.ts`.                                                          | `solveTriangle.ts`, `solveHelix.ts`, `solveCuttingData.ts`, `solveTolerance.ts`, `solveThread.ts`, `solveCylinderWeight.ts`                                                                                                       | Stable for calculation and lookup features.                                                                  |
| API types live in `api/types.ts`.                                                             | All seven features have an API types file, including `finishing/api/types.ts`.                                                                                                                                                    | Stable file name, but content is feature-specific.                                                           |
| Form factories live in feature domain files and use `createInitial*Form`.                     | `createInitialTriangleForm`, `createInitialHelixForm`, `createInitialCuttingDataForm`, `createInitialToleranceForm`, `createInitialThreadForm`, `createInitialFinishingForm`, `createInitialCylinderWeightForm`                   | Stable naming pattern.                                                                                       |
| Parse helpers use `parse*.ts`.                                                                | `parseTriangle.ts`, `parseHelix.ts`, `parseCuttingData.ts`, `parseTolerance.ts`, `parseThread.ts`, `parseFinishingPlan.ts`, `parseCylinderWeight.ts`                                                                              | Stable enough for generated placeholders.                                                                    |

| Routes are centralized in `src/app/routes.tsx`.                                               | All seven pages are imported and registered there.                                                                                                                                                                                | Route edits must check for duplicate paths and imports.                                                      |
| Rust command areas use `command.rs`, `mapping.rs`, `request.rs`, `response.rs`, and `mod.rs`. | Present under `src-tauri/src/interface/tauri/right_triangle`, `helix`, `cutting_data`, `tolerance`, `thread`, `finishing`, and `cylinder_weight`.                                                                                 | File names are stable, but command registration and contracts must remain manual unless explicitly reviewed. |
| Frontend cross-feature tests group representative forms and controllers.                      | `src/features/calculatorForms.test.tsx` and `src/features/controllerHooks.test.tsx` cover multiple features.                                                                                                                      | A generator should not automatically edit grouped tests without explicit intent.                             |

# Variable Conventions

| Variable structure                                       | Evidence                                                                                                                                                      | Why it differs                                                                                                       |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Feature directory casing differs.                        | `right_triangle`, `cylinder_weight`, `cuttingData`, `helix`, `threads`, `tolerances`, `finishing`                                                             | The repository already contains snake_case, camelCase, and plain lowercase feature directories.                      |
| Rust feature names may differ from frontend names.       | Frontend `cuttingData` maps to Rust `cutting_data`; frontend `tolerances` maps to Rust `tolerance`; frontend `threads` maps to Rust `thread`.                 | Rust module naming follows snake_case and sometimes singular naming.                                                 |
| Page location differs for finishing.                     | Other pages are under `ui`; finishing uses `src/features/finishing/page/FinishingPage.tsx`.                                                                   | Finishing is split into `plan`, `execution`, and `page` workflow areas.                                              |
| Top-level domain and UI folders are absent in finishing. | `src/features/finishing/plan/domain`, `src/features/finishing/execution/domain`, `src/features/finishing/plan/ui`, and `src/features/finishing/execution/ui`. | Domain and UI are scoped to workflow stages.                                                                         |
| History support is optional.                             | Present in `cuttingData`, `tolerances`, and `threads`; absent in `right_triangle`, `helix`, `finishing`, and `cylinder_weight`.                               | Only some features expose saved-result panels.                                                                       |
| Visual side panels are optional.                         | `right_triangle/ui/triangleFigure` and `helix/ui/helixFigure` exist; other features do not have figure folders.                                               | Geometry-oriented calculators include illustrations; other features use forms, histories, tables, or workflow views. |
| Lookup option state is feature-specific.                 | `threads/domain/threadOptions.ts`; `tolerances/domain/toleranceOptions.ts`, `toleranceSelection.ts`, and `ui/toleranceSelectState.ts`.                        | Lookup data shapes and selection rules differ between threads and tolerances.                                        |
| Request builders are not universal.                      | Most calculator-like features have `domain/buildRequest.ts`; `threads` does not.                                                                              | Thread request shape is coupled to loaded option selection rather than generic field-combination request building.   |
| Persistence is not a generic feature concern.            | Only cylinder materials use `JsonCylinderMaterialRepository` and `AppState.cylinder_material_repository`.                                                     | Other histories use frontend in-memory state or no persistence.                                                      |
| Backend state is not a generic feature concern.          | Finishing uses `AppState.finishing_execution`; cylinder materials use `AppState.cylinder_material_repository`.                                                | Stateless calculators do not require backend state.                                                                  |

| Generate CNC, geometry, tolerance, thread, or unit formulas | Domain rules live in Rust under `src-tauri/src/domain` and require domain-specific review.                                          |
| Invent Tauri request or response contracts                  | Existing mappings are explicit and feature-specific in frontend `api/solve*.ts`, `domain/buildRequest.ts`, and Rust interface DTOs. |
| Automatically register Rust commands                        | `src-tauri/src/lib.rs` wires real commands and app state; incomplete registration can break the Tauri boundary.                     |
| Generate database schemas or imported reference data        | Tolerance and thread features use bundled SQLite data and repository code.                                                          |
| Generate persistence repositories                           | The only durable user-editable repository is cylinder material JSON persistence.                                                    |
| Generate app-state fields                                   | `AppState` currently has only finishing execution and cylinder material repository state.                                           |
| Edit grouped tests automatically                            | `calculatorForms.test.tsx` and `controllerHooks.test.tsx` cover multiple features and need deliberate test cases.                   |
| Normalize existing naming                                   | The repository intentionally or historically contains snake_case, camelCase, singular, and plural feature names.                    |
| Create empty architectural layers                           | Several folders are optional and should appear only when files are needed.                                                          |
| Add dependencies or generator frameworks                    | `package.json` currently has no generator dependency, and the manifest is not an implementation task.                               |
